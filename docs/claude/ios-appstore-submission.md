## What to do on Mac (pick up here)

### Step 1: Pull the branch

```bash
git fetch origin
git checkout feature/ios-appstore-submission
git pull
```

### Step 2: Install CocoaPods (if not already installed)

```bash
brew install cocoapods
# OR: sudo gem install cocoapods
```

### Step 3: Run expo prebuild

```bash
cd frontend
npx expo prebuild --platform ios --no-install --no-clean
```

> The `ios/` project is committed and carries hand edits (`ci_scripts/`,
> `.xcode.env`, Podfile patches). Never pass `--clean`, and always pass
> `--no-clean` (SDK 58 cleans by default); see `docs/claude/ios-ci.md`.

This generates the `ios/` Xcode project from `app.json`. It will:
- Create `ios/BookShelfAI.xcworkspace`
- Burn `com.buffingchi.bookshelf` into the Xcode project
- Generate `ios/BookShelfAI/PrivacyInfo.xcprivacy` from the `privacyManifests` block

### Step 4: Install CocoaPods dependencies

```bash
cd ios
pod install
cd ../..
```

### Step 5: Verify the privacy manifest

```bash
cat frontend/ios/BookShelfAI/PrivacyInfo.xcprivacy
```

Should contain XML with `NSPrivacyAccessedAPICategoryUserDefaults` and reason `CA92.1`, and the collected data types listed in [App Privacy declarations](#app-privacy-declarations-privacy-manifest-and-store-labels). If the file is missing or wrong, see the Fallback section below.

### Step 6: Verify bundle ID

```bash
grep -r "com.buffingchi.bookshelf" frontend/ios/
```

Should show hits in `project.pbxproj` and `Info.plist`.

### Step 7: Run Jest tests

```bash
cd frontend
npx jest
```

All tests should pass — no TypeScript source was changed.

### Step 8: Commit and push the ios/ directory

```bash
git add frontend/ios/
git commit -m "feat(ios): add expo prebuild bare workflow ios/ directory

Co-Authored-By: Claude Sonnet 4.6 <noreply@anthropic.com>"
git push
```

## After the ios/ commit — Apple account setup

### Step 1: Enroll in Apple Developer Program
1. Go to `https://developer.apple.com/programs/enroll/`
2. Sign in with your Apple ID (wcmchenry3@gmail.com)
3. Select **Individual / Sole Proprietor**
4. Enter legal name exactly as on government ID
5. Pay $99 USD/year
6. Enable 2FA on your Apple ID first — required for enrollment
7. Approval is usually same-day for individuals (up to 48h)

### Step 2: Accept agreements in App Store Connect
1. Go to `https://appstoreconnect.apple.com`
2. Agreements, Tax, and Banking → accept Paid Applications Agreement
3. Fill in tax + banking info (required even for free apps)

### Step 3: Create App ID + App Store Connect record
1. **Developer portal** → Certificates, Identifiers & Profiles → Identifiers → "+"
   - Type: App IDs → App
   - Description: `Bookshelf`
   - Bundle ID: **Explicit** → `com.buffingchi.bookshelf` (copy-paste this exactly)
   - Save
2. **App Store Connect** → My Apps → "+" → New App
   - Platform: iOS
   - Name: `Bookshelf` (if taken, try `Bookshelf: Reading Tracker`)
   - Bundle ID: select `com.buffingchi.bookshelf`
   - SKU: `bookshelf-ios-001`

### Step 4: Add privacy policy URL to App Store Connect
- App Information → Privacy Policy URL → `https://wcmchenry3-stack.github.io/book_app/privacy.html`
- Verify the URL loads in a browser first
- App Privacy → answer the data collection questions from [App Privacy declarations](#app-privacy-declarations-privacy-manifest-and-store-labels) (the answers must match the privacy manifest)

### Step 5: Build and archive in Xcode
1. Open `frontend/ios/BookShelfAI.xcworkspace` in Xcode
2. Signing & Capabilities → check **Automatically manage signing** → Team: your account
3. Bundle Identifier must show `com.buffingchi.bookshelf`
4. Destination → **Any iOS Device (arm64)** — NOT a simulator
5. **Product → Archive** (3–10 min)
6. Organizer → **Distribute App → App Store Connect → Upload**
7. Leave all defaults → Upload
8. Processing takes 5–30 min; email confirmation when done

### Step 6: Set up TestFlight
1. App Store Connect → your app → TestFlight tab
2. Find the build under iOS Builds
3. If yellow warning icon: click → answer encryption questions (or it's pre-answered by `ITSAppUsesNonExemptEncryption: false`)
4. Internal Testing → "+" → add testers by Apple ID email
5. Testers must be in Users and Access first
6. Enable build for the group → testers get TestFlight invite email

## Fallback: PrivacyInfo.xcprivacy not generated by prebuild

`frontend/ios/BookShelfAI/PrivacyInfo.xcprivacy` is committed and is already in
the Xcode project. If it is missing or wrong after prebuild, restore the
committed file (`git checkout -- frontend/ios/BookShelfAI/PrivacyInfo.xcprivacy`)
or regenerate it from `app.json` with
`npx expo prebuild --platform ios --no-install --no-clean`, then follow the
steps in `docs/claude/ios-ci.md`: re-indent the plist with tabs like the
committed file, and revert the unrelated prebuild churn in `project.pbxproj`,
`Info.plist` and the app icon (see the restore table there). Do not write it by
hand: `__tests__/unit/IosPrivacyManifest.test.ts` fails when it differs from
`app.json` `ios.privacyManifests`.

## App Privacy declarations (privacy manifest and store labels)

`frontend/app.json` `ios.privacyManifests.NSPrivacyCollectedDataTypes` declares
the data the app sends off the device (#1001), and prebuild copies it into
`frontend/ios/BookShelfAI/PrivacyInfo.xcprivacy`. Nothing is used for tracking
(`NSPrivacyTracking` is `false`, no tracking domains, no ATT prompt).
`__tests__/unit/IosPrivacyManifest.test.ts` pins this list and checks that the
committed plist matches `app.json`, so change both together (edit `app.json`,
then regenerate). Prebuild merges into the committed plist and appends new
types at the end, so add a new type at the end of the `app.json` list too.
Prebuild only appends missing types and adds purposes; it never removes a type or
rewrites Linked or Tracking. To remove a type or change Linked/Tracking/purposes,
delete that entry from `PrivacyInfo.xcprivacy` (or the whole file) before prebuild,
or edit the entry by hand to match `app.json`; the test catches any mismatch.

| Data type (manifest key `NSPrivacyCollectedDataType…`) | Linked to the user | Purposes | Where it comes from |
|---|---|---|---|
| Photos or Videos (`PhotosorVideos`) | No (owner decision, #1001) | App Functionality | Shelf / cover scan photos go to our server and on to the AI provider (Anthropic); the server keeps only a fingerprint and the books found |
| Email Address (`EmailAddress`) | Yes | App Functionality | Google sign-in; `users.email` |
| Name (`Name`) | Yes | App Functionality | Google profile name; `users.display_name`. `users.avatar_url` (the Google `picture` claim) is a URL from Google's ID token, not a photo taken from the device: it is covered by Name / Other User Content, not Photos |
| User ID (`UserID`) | Yes | App Functionality | Google account id (`users.google_id`) and our user id |
| Other User Content (`OtherUserContent`) | Yes | App Functionality | Library and wishlist entries, notes, ratings, books added by hand |
| Customer Support (`CustomerSupport`) | No | App Functionality | In-app feedback (text and, for a bug, redacted session logs) sent to Sentry User Feedback with no account details |
| Product Interaction (`ProductInteraction`) | Yes | App Functionality, Analytics | Per-user scan usage ledger and quota (`ai_usage`), whether a saved scan result was edited (`scan_corrections`), Sentry touch breadcrumbs |
| Crash Data (`CrashData`) | No | App Functionality | Sentry crash reports from the app (no user set on the device) |
| Performance Data (`PerformanceData`) | Yes | App Functionality | Sentry traces from the app and the API; API traces carry our user id |
| Other Diagnostic Data (`OtherDiagnosticData`) | Yes | App Functionality | Sentry error events and breadcrumbs; API error events carry our user id |
| Search History (`SearchHistory`) | No | App Functionality | Text searches are sent as `GET /books/search?q=<text>` (`lib/scan/executeScan.ts`). Not linked, on the same basis as device Crash Data: backend Sentry strips query strings (`backend/app/core/sentry_context.py`) and device transactions strip URL queries (`frontend/lib/sentryScrub.ts`), so `?q=` survives only in device error-event breadcrumbs, which carry no user, and in the uvicorn access log on Render, which has no account id and records Render's proxy IP (`--no-proxy-headers`), not the user's. #1029 stops collecting it; remove this row when it ships |

**Third parties and identifiers.**

- **Cloudflare Turnstile** (`components/TurnstileWidget.tsx`, mounted for every
  scan in `app/_layout.tsx`) runs in a WebView, so Cloudflare sees device and
  browser signals and the IP address to tell people from bots. This counts as
  App Functionality (Apple lists fraud prevention and security under it). No
  separate data type is declared: the signals are used only for the challenge,
  we receive only a pass/fail token, and nothing is stored with the account or
  used for tracking.
- **Sentry per-install id**: a random UUID the Sentry SDK makes for each
  install. It is not Apple's "Device ID" (an advertising or device-level
  identifier) and it is covered by the diagnostics types above.
- **Device attestation** is not live: the app never calls `/attestation/*`.
  When it ships (#753 / #870), declare **Device ID, linked to the user**,
  because `device_keys.key_id` is stored with `user_id`.

**Store answers.** Answer App Store Connect → App Privacy with the table above
(Tracking No for every type). In Play Console → Data safety, map the same list:
Email address, Name and User IDs (Personal info); Photos (Photos and videos,
processed ephemerally); App interactions, In-app search history and Other
user-generated content (App activity); Crash logs and Diagnostics (App info and
performance). Data is encrypted in transit, users can request deletion, and
nothing is used for advertising or tracking.

When a feature starts sending new data off the device, add the type
here, in `app.json`, and in the store answers in the same change. To remove a
type or change its Linked/Tracking/purposes, delete that entry from
`PrivacyInfo.xcprivacy` (or the whole file) before prebuild, or edit the entry by
hand to match `app.json`; the test catches any mismatch.
