# Git Workflow

See [~/.claude/standards/git.md](~/.claude/standards/git.md) for the full workflow, branching strategy, conventional commits, and PR process.

## book_app specific
- Squash merge into `dev`; merge commit into `main` for releases
- Draft PRs only — Claude opens them; user reviews and merges

## Hooks (`.claude/hooks/`, registered in `.claude/settings.json`)
PreToolUse hooks block with exit code 2 and the reason on stderr (`lib/output.sh`). They are guardrails for Claude sessions only; CI commitlint and branch protection remain the real enforcement.

**One rule:** `git commit` and `git push` run alone, and you push the branch you are on. A command line containing a commit or push may share it only with `git add`/`status`/`diff`/`log` (before) or `git status`/`log` (after). `cd`, `pushd`, env prefixes (`GIT_DIR=`), `--git-dir`/`--work-tree`, `git -c`/`--config-env`, subshells, `eval`/`bash -c`/`sh -c`/`command`/`env`, any other git subcommand (checkout, switch, merge, ...) or a second commit/push is blocked, so the gate checks the exact repo and branch. `git -C <dir>` is honoured. A push may name only the current branch: no refspec, `origin`, `origin HEAD`, `origin <current>`, `HEAD:<x>` or `<current>:<x>`, with flags like `-u`/`--force-with-lease`. Only these push flags are accepted: `-u/--set-upstream`, `--force-with-lease[=..]`, `--force-if-includes`, `-v`, `-q`, `-n/--dry-run`, `--[no-]progress`, `-d/--delete` (so no `--all/--branches/--mirror/--tags/--force/--prune/--repo`). The gates fail closed: if a command mentions commit/push/`pr create` but cannot be parsed (unbalanced quotes, ...), it is blocked; shell comments are ignored. Any other source ref (or a bare `:` matching refspec) is blocked; with no refspec, a configured `remote.<name>.push` or `push.default` of `matching`/`nothing` is blocked (push with an explicit refspec); a remote with `remote.<name>.mirror` set is always blocked (with no remote named, the gate resolves it like git: `branch.<b>.pushRemote`, `remote.pushDefault`, `branch.<b>.remote`, `origin`); delete pushes (`--delete`, `:branch`) skip the precheck.
- `commit-gate.sh` — `git commit`: blocks on `dev`/`main` and non-Conventional messages (`-m`, multiple `-m`, `-F file`, heredoc forms; editor/unknown message is allowed). Rules mirror commitlint config-conventional (types, header <= 100, lower-case subject, no trailing period).
- `pr-title-gate.sh` — `gh pr create` and `mcp__github__create_pull_request`: Conventional title; `--base` is required and must be `dev` (`main` only with an explicit `--head dev` or `--head release-please--*`); `-R/--repo` before or after `pr`, attached short values (`-tX`, `-BX`), `VAR=x` prefixes and the `gh pr new` alias are understood; every `gh pr create` flag's value is consumed (so `--body "--base=dev"` is body text) and an unknown flag or stray argument blocks; `gh pr create` behind `env`/`command`/`bash -c`/`eval` is blocked.
- `precheck-gate.sh` — `git push`: ruff/black (backend) and eslint/prettier (frontend) on files changed vs `origin/dev`, plus `npm run typecheck` when anything under `frontend/` changed (deletions and config included); per-file checks lint the committed snapshot (`HEAD:<path>`), never uncommitted edits; `npm run typecheck` runs on the working copy, so the push is blocked while `frontend/` has uncommitted or untracked changes; changed filenames are read NUL-delimited, so non-ASCII names are checked too; uncommitted or untracked lint/format config (`backend/pyproject.toml`, ESLint/Prettier config, `frontend/package.json`, `tsconfig*.json`) blocks the push, since linters read config from the working copy; a pass is cached 24h per tree hash in `${XDG_CACHE_HOME:-~/.cache}/bookshelf-claude-hooks/`. Missing tools only warn. See the one rule above. The PR-title gate validates every `gh pr create` in a command line (first failure blocks).
- `lint-gate.sh`, `policy-gate.sh` — block `gh pr create` on lint failures / policy-relevant changes. `policy-gate.sh` reads its global skip regex (`_global_skip`) from `.claude/policies/policy-patterns.json`.
- `lint-on-edit.sh` — PostToolUse lint of the edited file.

Tests: `backend/tests/unit/test_claude_hooks.py`.
